# MI300X and ROCm runtime

This branch targets AMD MI300X (`gfx942`) with Python 3.11, ROCm/HIP 7.0, and
PyTorch `2.10.0+rocm7.0`. The checked-in environment lock also fingerprints the
exact SGLang and AITER commits plus their current uncommitted patch hashes.

## Shared environment

`~/.config/agent4kernel/env.sh` must export:

```bash
export GPU_VENV=/absolute/path/to/rocm-python-environment
export SGLANG_ROOT=/absolute/path/to/sglang
export AITER_ROOT=/absolute/path/to/aiter
```

Run:

```bash
./bootstrap.sh
./run.sh check
./bench.sh env --json
./bench.sh validate
```

Bootstrap never downloads or installs GPU packages. It validates the shared
environment and creates `.runtime/venv` as a symlink to `$GPU_VENV`. It refuses
to replace a real file or directory at that path. Launchers discard inherited
`PYTHONPATH` and reconstruct it from this repository, `$SGLANG_ROOT/python`,
and `$AITER_ROOT`.

All cache, lock, log, result, JIT, and benchmark artifacts remain ignored and
repository-local. None are source-controlled.

## Device identity and locking

For a numeric logical device, the engine applies this precedence:

1. `ROCR_VISIBLE_DEVICES`;
2. `HIP_VISIBLE_DEVICES`;
3. `CUDA_VISIBLE_DEVICES`;
4. the unfiltered KFD topology order.

It maps the selected entry through `/sys/class/kfd/kfd/topology/nodes`, using
AMD vendor ID, `gpu_id`, `location_id`, render minor, and gfx target. The
resulting physical identity owns one cross-process lock under `.runtime/locks`.
If KFD is unavailable, the engine may use PyTorch UUID discovery; the
`gpu_identity_resolution` telemetry then states that fallback explicitly.

## HIP timers

ROCm PyTorch deliberately exposes HIP functionality through `torch.cuda`.
Therefore the CLI names remain:

- `cuda_event`: HIP event timing;
- `cuda_graph`: HIP graph capture and replay;
- `auto`: try graph capture, then explicitly fall back to event timing;
- `wall_clock`: synchronized host timing.

Reference and candidate must resolve to the same effective timer. A different
timer, failed correctness, unstable samples, competing GPU activity, or
incomplete telemetry makes the row ineligible for ranking.

## Smoke acceptance

The MI300X validation operator is `example_rocm_bf16_gemm`. Its control
candidate calls the same PyTorch BF16 GEMM contract on independently cloned
inputs. It includes:

- smoke: `M=N=K=256`;
- representative: `M=1024, N=4096, K=4096`;
- theoretical cost: `2MNK` FLOPs plus input, weight, and output bytes;
- explicit BF16 tolerance;
- 5 warmups, 30 samples, and 20 inner iterations with `auto` timing.

Run it on one idle device:

```bash
ROCR_VISIBLE_DEVICES=0 HIP_VISIBLE_DEVICES=0 CUDA_VISIBLE_DEVICES=0 \
  ./bench.sh run --suite mi300x_smoke
```

A release-quality result must contain the manifest, environment fingerprint,
correctness rows, 60 interleaved raw samples per case (30 per role), KFD lock
metadata, matching effective timers, and `ranking_eligible=true`.
